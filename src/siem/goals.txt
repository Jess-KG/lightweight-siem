LIGHTWEIGHT WINDOWS SIEM — DETECTION ROADMAP
================================================

Goal:
Build a lightweight SIEM capable of detecting suspicious Windows activity,
correlating related events, generating alerts, and allowing investigation.

Primary detection categories:
1. Authentication & Account Attacks
2. Execution
3. PowerShell
4. Process & Parent/Child Behaviour
5. Persistence
6. Privilege Escalation
7. Credential Access
8. Discovery
9. Lateral Movement
10. Defense Evasion
11. Command & Control
12. Collection
13. Exfiltration
14. Malware / Security Tool Detections
15. Account & Security Changes
16. Multi-stage Attack Correlation


================================================
1. AUTHENTICATION & ACCOUNT ATTACKS
================================================

Detect:

- Multiple failed logins from the same source
- Multiple failed logins against the same account
- Multiple failed logins against multiple accounts
- Brute-force attacks
- Password spraying
- Successful login following repeated failed logins
- Successful login after a long period of inactivity
- Unusual logon type
- Interactive logon by unexpected account
- Remote interactive/RDP logon
- Network logon
- Explicit credential usage
- Privileged account login
- Disabled account attempting authentication
- Locked account activity
- Account created
- Account deleted
- Account enabled
- Account disabled
- Account password changed
- Account password reset
- User added to privileged group
- User removed from privileged group
- Unexpected administrator account activity
- Guest account enabled
- Default account activity
- Authentication occurring across multiple hosts


CORRELATION EXAMPLES:

Failed login
+ Failed login
+ Failed login
+ Failed login
+ Successful login
= Possible brute-force compromise


One account
+ authenticates to many hosts
+ within a short time window
= Possible lateral movement


================================================
2. PROCESS EXECUTION
================================================

Detect:

- Suspicious process creation
- Processes launched from temporary directories
- Processes launched from user-writable directories
- Executables launched from unusual locations
- Suspicious command-line arguments
- Unusual parent/child process relationships
- Office application spawning command shells
- Browser spawning command shells
- Script interpreter spawning suspicious processes
- System process spawning unusual applications
- Unexpected SYSTEM-level process execution
- Process execution by unusual users
- Unsigned/suspicious executables
- Execution of newly created files
- Execution of files from network shares
- Execution from removable media


High-value process chains:

WINWORD.EXE
    -> cmd.exe
    -> powershell.exe

EXCEL.EXE
    -> powershell.exe

OUTLOOK.EXE
    -> powershell.exe

powershell.exe
    -> cmd.exe

wscript.exe
    -> powershell.exe

mshta.exe
    -> powershell.exe

rundll32.exe
    -> suspicious DLL

regsvr32.exe
    -> suspicious DLL

These should generate stronger alerts than isolated process events.

16. HIGH-VALUE CORRELATION RULES
================================================

These should be a major focus of the SIEM.

RULE 1 — BRUTE FORCE

Multiple failed logins
+ same account/source
+ short time window
= Possible brute force


RULE 2 — BRUTE FORCE SUCCESS

Multiple failed logins
+ successful login
= Possible compromised account


RULE 3 — PASSWORD SPRAY

Failed logins
+ many different accounts
+ same source
+ short time window
= Possible password spraying


RULE 4 — SUSPICIOUS POWERSHELL

PowerShell
+ encoded/hidden command
+ suspicious parent
= High-risk PowerShell activity


RULE 5 — OFFICE EXPLOITATION

Office application
+ command shell
+ PowerShell/script interpreter
= Possible malicious document execution


RULE 6 — CREDENTIAL DUMPING

Suspicious process
+ LSASS access
= Possible credential dumping


RULE 7 — DISCOVERY BURST

Multiple discovery commands
+ same host/user
+ short time window
= Possible reconnaissance


RULE 8 — PERSISTENCE

New service OR scheduled task OR registry persistence
+ suspicious executable
= Possible persistence


RULE 9 — LATERAL MOVEMENT

Successful remote authentication
+ remote execution
= Possible lateral movement


RULE 10 — MULTI-HOST LATERAL MOVEMENT

Same account
+ successful authentication to multiple hosts
+ short time window
= Possible lateral movement


RULE 11 — DEFENSE EVASION

Security configuration change
+ suspicious process
= Possible defense evasion


RULE 12 — LOG TAMPERING

Security log cleared
OR event logging disabled
= High-severity alert


RULE 13 — C2

Suspicious process
+ outbound network connection
= Possible C2


RULE 14 — COLLECTION

File discovery
+ sensitive file access
+ archive creation
= Possible data collection


RULE 15 — EXFILTRATION

Data collection
+ archive creation
+ unusual outbound connection
= Possible exfiltration


RULE 16 — ATTACK CHAIN

        ↓

        ↓
Credential access
        ↓
Persistence
        ↓

        ↓

= Possible multi-stage compromise


================================================
17. ALERT SEVERITY
================================================

LOW:
- Single suspicious discovery event
- Unusual but low-confidence activity

MEDIUM:
- Multiple suspicious events
- Discovery burst
- Repeated failed logins
- Suspicious PowerShell

HIGH:
- Successful login after brute force
- Credential access
- Persistence
- Lateral movement
- Security logging modification
- Suspicious C2

CRITICAL:
- Credential dumping + lateral movement
- Security controls disabled + suspicious execution
- Malware + persistence + C2
- Multi-stage attack chain
- Confirmed compromise indicators


================================================
18. WHAT EACH ALERT SHOULD CONTAIN
================================================

Every alert should contain:

- Alert ID
- Alert name
- Severity
- Detection rule
- MITRE ATT&CK tactic
- MITRE ATT&CK technique
- Timestamp
- Host/computer
- User/account
- Source IP
- Destination IP
- Process
- Parent process
- Command line
- Triggering event IDs
- Number of related events
- Time window
- Detection explanation
- Recommended investigation action


Example:

ALERT ID: ALT-00042
NAME: Possible Credential Dumping
SEVERITY: HIGH

Host: PC01
User: Administrator
Process: suspicious.exe
Technique: OS Credential Dumping
Events: 2
Time window: 14 seconds

Reason:
A suspicious process accessed LSASS shortly after execution.

Related events:
- Process creation
- LSASS access

Recommended action:
Investigate process, user account, and subsequent authentication activity.

================================================
20. OVERALL GOAL
================================================

The SIEM should NOT simply answer:

"What event happened?"

It should eventually answer:

"What is happening?"

"Is it suspicious?"

"Why is it suspicious?"

"What other events are related?"

"Which host/user/process is involved?"

"What MITRE ATT&CK technique does it represent?"

"Could these events be part of the same attack?"

"What should the analyst investigate next?"


The ultimate detection pipeline:

RAW EVENT
    ↓
NORMALISE
    ↓
STORE
    ↓
CLASSIFY
    ↓
DETECT
    ↓
CORRELATE
    ↓
SCORE
    ↓
ALERT
    ↓
INVESTIGATE
    ↓
ATTACK TIMELINE
